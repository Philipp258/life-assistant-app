# Rating rubric

For each scenario, record three things.

## Status

- **green** — the user goal was achieved without meaningful friction.
- **yellow** — the user goal was achieved, but something was confusing,
  ugly, slow, or required a workaround a real user might not find.
- **red** — the user goal was not achieved, or only achieved by
  reading the code / bypassing the intended path.

## Severity (only if not green)

- **cosmetic** — visual or wording issue, no behavior impact.
- **friction** — a real user would get through it, but annoyed or
  delayed.
- **blocker** — a real user would give up, lose data, or be unable to
  proceed.

## Freeform

Use judgment. Keep it short but specific, and record anything that
affected your confidence in the release: confusing, ugly, brittle,
surprising, especially good, or worth checking again.

Numbers help when you have them, such as retries or error codes. Do
not invent them.
